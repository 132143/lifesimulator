# 打包与分发指南（做移植 / 分享给朋友）

本文说明怎么把这个游戏打成**"解压即玩、存档同文件夹"**的压缩包，以及包里放了哪些文件、为什么。

---

## 一、最快的做法（一条命令）

在项目根目录（含 `LifeSimulator.py` 和 `启动游戏.bat` 的目录）执行：

```bat
python dev_tools\package_release.py
```

产物：

```
release\LifeSimulator_v3.0_便携版.zip      ← 只发给朋友玩，约 123 KB
```

想额外带上模块化源码与测试脚本（给自己或会改代码的朋友）：

```bat
python dev_tools\package_release.py --with-source
→ release\LifeSimulator_v3.0_含源码.zip
```

其他参数：

```bat
python dev_tools\package_release.py --out D:\我的输出目录     :: 指定输出目录
python dev_tools\package_release.py --zip-name 人生模拟器.zip  :: 指定包名
```

## 二、压缩包里有哪些文件（玩家版）

| 压缩包内路径 | 作用 | 必需？ |
| --- | --- | --- |
| `LifeSimulator.py` | 游戏本体（单文件，约 400 KB） | **必需** |
| `启动游戏.bat` | 双击即玩；自动找 Python、自动建 `save\`、传 `--portable` | **必需** |
| `portable.txt` | 便携模式标记：存档放同目录的 `save\` 里 | **必需** |
| `使用说明.txt` | 给朋友的说明（怎么启动、没 Python 怎么办、存档在哪） | 建议 |
| `README.md` | 完整文档（玩法、机制、模组说明） | 建议 |
| `docs\模组开发指南.md` | 想加模组的看这个 | 可选 |
| `save\` | 空目录：存档位置一目了然 | **必需（空目录）** |
| `save\mods\` | 空目录：模组放这里 | 可选 |
| `版本信息.txt` | 自动生成的版本与打包时间 | 可选 |

**总共 9 个条目、压缩后约 123 KB。**

> 注意：`save\` 与 `save\mods\` 必须是**空目录**（包里靠目录条目保留），
> 不要把自己的存档打进去，否则会覆盖朋友的进度。

## 三、存档为什么能"跟文件夹走"

游戏里内置了**便携模式**（`resolve_base_dir()`）：

```
数据目录的判定优先级：
  1. 环境变量 LIFESIM_HOME        （调试/多开用）
  2. 便携模式：程序目录\save\      ← 解压版走这条
  3. D:\desktop\LifeSimulator     （源码开发的默认位置）
  4. 兜底：用户主目录\LifeSimulator → 程序目录\data
```

**便携模式的判定**（`is_portable_mode()`）：

| 条件 | 结果 |
| --- | --- |
| 程序目录有 `no_portable.txt` | 强制**关闭**便携模式 |
| 程序目录有 `portable.txt` | 强制**开启** |
| 程序目录已存在 `save\` | **开启** |
| 程序目录有 `启动游戏.bat` / `README.md` / `使用说明.txt` 等分发标志文件 | **开启**（自动识别"这是解压包"） |
| 以上都不满足（纯源码开发目录） | 关闭，用默认目录 |

所以：**朋友解压后，即使没有 `portable.txt`，只要文件夹里有 `启动游戏.bat`，也会自动进入便携模式。**
`启动游戏.bat` 里还额外显式传了 `--portable`，双保险。

实测（见 `dev_tools/test_portable.py`，11 项全通过）：

```
[OK] 自检在解压目录下可运行
[OK] 数据目录指向解压目录内的 save\
[OK] 存档生成在 解压目录\save\save.json（84 KB）
[OK] 人生日志生成在 解压目录\save\life_log.txt
[OK] 从解压目录的 save.json 读档成功
[OK] 整个文件夹搬走后存档仍在（存档跟着文件夹走）
[OK] 搬走后数据目录自动指向新位置的 save\
[OK] no_portable.txt 可强制关闭便携模式
```

## 四、朋友那边的体验

1. 收到 `LifeSimulator_v3.0_便携版.zip`（约 123 KB）
2. 解压到任意文件夹（例如桌面）
3. **双击 `启动游戏.bat`**
   - 会自动建 `save\` 目录
   - 自动进入便携模式（存档就在同级 `save\` 里）
4. 玩完点「保存并退出」
5. 那个文件夹可以随便拷贝 / 放 U 盘 / 备份，存档跟着走

**朋友需要装 Python 吗？** 需要一次（官方安装包约 25 MB），
但**不需要 pip 安装任何东西**——游戏只用标准库（tkinter / json / random / os 等）。
`启动游戏.bat` 里已写好没装 Python 时的提示与下载地址。

## 五、免安装 exe 版（朋友完全不用装 Python）

一条命令搞定：

```bat
python dev_tools\build_exe.py
→ release\LifeSimulator_v3.0_免安装版.zip     （约 10 MB，946 个条目）
```

脚本会自动：安装/调用 PyInstaller → 打包 exe → 组装 `save\`、`portable.txt`、
免安装版说明 → 生成压缩包。产物结构：

```
LifeSimulator.exe        1.9 MB   主程序（双击即玩）
_internal\               25 MB    Python 运行时与依赖（必须一起保留）
启动游戏.bat                      备选启动方式（被杀软拦截时用）
portable.txt                      便携标记：存档放同目录
使用说明.txt / README.md / docs\  文档
save\  save\mods\                 存档与模组目录
```

**为什么用「目录式」而不是单文件 exe？**

| 方式 | 优点 | 缺点 |
| --- | --- | --- |
| **目录式（默认）** | 启动快（1~2 秒）、兼容性好、不易被杀软误报 | 解压后文件较多（946 个） |
| 单文件 `--onefile` | 只有一个 exe，最简洁 | 每次启动要解压到系统临时目录；若临时目录被组策略/杀软限制，会启动失败 |

想要单文件版：`python dev_tools\build_exe.py --onefile`

**打包时会用到的第三方库**：PyInstaller（只在打包时需要）。
游戏**运行**时依然只用 Python 标准库；打完的 exe 里已内置 Python 运行时。

**技术细节（为什么需要 run_frozen.py）**：主程序是单文件、用 `importlib` 动态加载的，
PyInstaller 的静态分析看不到它，所以用一个显式 `import` 的引导脚本
`run_frozen.py` 把主模块纳入依赖收集，并把同一个模块对象注册进 `sys.modules`
（保证模组系统与全局注册表不会分裂成两份）。

**已知情况**：
* 部分公司电脑/学校电脑启用了 **应用程序控制策略（WDAC/AppLocker）**，
  会提示"An Application Control policy has blocked this file"，
  此时请改用源码版（便携版包）跑。
* 打包成 exe 后 `program_dir()` 返回 exe 所在目录，**便携模式照常生效**（存档仍在同级 `save\`）。
* 缺 `VCRUNTIME140.dll` 时装一次「Microsoft Visual C++ 运行库」即可。

## 七、常见问题

**Q：能只发 `LifeSimulator.py` 一个文件吗？**
能，但朋友得自己用命令行跑 `python LifeSimulator.py --portable`；
而且没有 `启动游戏.bat` 时，程序不一定判定为便携模式（可能写到默认目录）。
想"双击即玩 + 存档同目录"，还是打包整个 zip 更稳。

**Q：朋友想同时玩两个存档？**
把整个文件夹复制一份即可：两份各有独立的 `save\`，互不影响。

**Q：想更新版本但不丢存档？**
把新的 `LifeSimulator.py`（和 `启动游戏.bat`）覆盖过去，`save\` 别动即可。

**Q：`no_portable.txt` 有什么用？**
放在程序目录可强制关闭便携模式（回到默认数据目录）。
开发目录里就放了它，避免开发时的存档被写进源码目录。
